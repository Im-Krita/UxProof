# UXProof — короткий текст для защиты

## Проблема

При тестировании интерфейса недостаточно понять, как выглядит экран. Нужно проверить, способен ли пользователь **закончить действие**: выбрать сервер, сохранить настройку, вернуться назад. И важно не только получить замечание, но и показать, где оно воспроизводится.

## Решение

UXProof запускает браузер, проходит заданные действия пользователя на нескольких экранах и показывает, какой шаг сломался. Система собирает скриншот, шаг воспроизведения, JavaScript ошибки и результаты accessibility-проверки. Отдельно можно попросить модель дать рекомендации по визуальному UX, но они **не смешиваются** с технически подтверждёнными проблемами.

Отчёт выгружается в JSON, HTML и Excel. Модель может не только смотреть скриншоты, но и **предложить шаги сценария по тексту цели**; предложение проходит ту же валидацию, что и ручной ввод, и запускается только после подтверждения человеком.

## Демонстрация за 100 секунд

1. В тестовом Relay выбираю сценарии и три размера экрана.
2. Запускаю аудит: Playwright реально взаимодействует с интерфейсом.
3. Показываю отсутствие подтверждения сохранения и скрытую кнопку возврата на мобильном.
4. Кликаю на дефект, вижу точный шаг и скриншот с рамкой элемента.
5. Показываю JSON, HTML и Excel для разработчика, затем прогон на `/fixed`: дефекты шагов закрыты, а замечание axe остаётся «не подтверждённым автоматически».
6. Показываю одно и то же снаружи: локальный API и MCP-вызов `list_reports` возвращают сводку без скриншотов.

## Чем это отличается от анализа скриншота нейросетью

Экран сам по себе не показывает, работает ли переход. UXProof записывает **результат конкретного действия**. Модель здесь — не судья, а помощник по поиску потенциальных улучшений и генератор черновика шагов.

## Чего не говорить

Не говорить, что агент сам умеет исследовать абсолютно любой UI без сценария; что UXProof надёжнее всех коммерческих сервисов; что найдено 95% ошибок; что установщик проверен на чистой Windows без Node и WebView2 — MSI уже содержит Node и Chromium, но установка на чистую VM ещё не подтверждена. MCP работает только против запущенного локального API, а не упакованного приложения. Всё перечисленное требует отдельных доказательств.
