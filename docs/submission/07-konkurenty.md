# Сравнение по задаче

Цифр «мы точнее конкурентов» нет. Ниже: какой вопрос закрывает каждый инструмент и какой закрывает UXProof. Список неполный.

## Автотесты в коде

Playwright Test и Cypress гоняют реальный браузер по скрипту. Отчёт рассчитан на разработчика: лог, trace, ассерт. Чтобы получить «шаг + PNG + axe» без написания теста, эти инструменты сами по себе не предназначены.

UXProof даёт те же клики через Playwright, но сценарий собирается в UI. Типы шагов ограничены белым списком; `eval` нет.

## Страница и WCAG

Lighthouse и axe DevTools смотрят текущую страницу: производительность, выбранные правила доступности. Они не проходят сценарий «сохранить → появился status» и не кликают «На главную» на трёх ширинах.

UXProof вызывает axe-core внутри прогона после шагов. Ноль замечаний axe не равен полному WCAG.

## Визуальный diff

Percy и Applitools сравнивают пиксели или снимки между сборками. Они отвечают «экран изменился», а не «клик дошёл и статус появился».

UXProof пишет PNG упавшего шага и конечный снимок прогона. Пофайлового pixel-diff нет.

## Люди

Maze, UserTesting и аналогичные сервисы собирают поведение живых людей. Это другой бюджет и другой протокол.

UXProof гоняет заданный сценарий локально, без панели респондентов.

## Скриншот в чат с моделью

Модель по картинке выдаёт гипотезы. Шаг она не исполняет. В UXProof тот же класс выхода помечен `recommendation` и отделён от `confirmed`. Живой платный OpenAI в этом срезе не вызывался; локальный Ollama вызывался.

## Что делает UXProof на этом фоне

Сценарий без кода, три viewport, bundled Node и Chromium в Windows MSI, отчёт JSON/HTML/Excel, сравнение `/` и `/fixed` по идентификаторам находок (ошибка шага может стать `resolved`; исчезнувшее axe-замечание само по себе не объявляется исправленным).

Чего нет: облачная ферма браузеров, fuzzy UX-регрессии, агент «сам обойдёт любой сайт», подпись установщика, прогон MSI на образе без WebView2.
