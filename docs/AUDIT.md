# Дополнение к C03

Runtime-проверка нового нормализованного расширения выполняется перед записью отчёта. При чтении истории проверяются поля, нужные интерфейсу; неполные записи пропускаются без удаления файлов. Полная проверка нормализованного расширения исторических отчётов ещё не реализована; см. `CORE-IMPLEMENTATION-STATUS.md`.

Нормализация v0.2 дополнена наблюдениями упавших шагов Playwright. Сопоставление использует fingerprint определения сценария и остаётся консервативным при изменениях сценария.

## BUG-016 — параллельные Tauri IPC-запуски

Блокировка Node была локальной для процесса, тогда как Rust создаёт отдельный Node-процесс для каждого IPC-вызова. Добавлены блокировки в Rust и через файл app-data; тесты проверяют потоки, отдельный процесс и освобождение. Реальный конкурентный вызов через окно Tauri пока не проверен. Web dev API не разделяет эту блокировку.

## BUG-017 — значения сценариев в файлах и скриншотах

Ранее Tauri записывал входную конфигурацию в `input.json`, а ошибки проверок могли содержать фактические и ожидаемые значения. Новые запуски передают конфигурацию по stdin, значения из ошибок проверок исключены; чувствительные поля и непрозрачные поверхности маскируются на PNG. Это частичное исправление: старые файлы не удаляются, а секреты в произвольном видимом тексте и сообщениях страницы ещё могут попасть в отчёт.

## BUG-018 — лишние файлы runner в установщике

Упаковка включала весь `runner`, включая потенциальный локальный `.env`; release мог предпочесть исходный checkout упакованным ресурсам. Ресурсы перечислены явно, release выбирает упакованный runner. Два фиктивных файла корня `runner` отсутствовали в манифестах MSI и NSIS, а отдельный набор выбранных ресурсов прошёл локальный Chromium smoke. Выбранные каталоги зависимостей всё ещё включаются целиком; чистая VM и автономность не проверены.

## BUG-019 — redirect и DNS обходили проверку сети

Playwright вызывает route-обработчик только для первого URL цепочки redirect ([документация](https://playwright.dev/docs/api/class-page#page-route)); прежняя проверка DNS также не закрепляла адрес соединения. Добавлен локальный аутентифицированный прокси, который проверяет назначения и использует только разрешённые IP. Локальные тесты подтверждают блокировку redirect к адресу метаданных и подмены DNS, а также работу разрешённых HTTP, HTTPS и WebSocket. Контрольный тест WebRTC/STUN на текущей Windows-машине не увидел UDP при включённой политике. Это не доказательство полной OS-изоляции, поддержки нестандартных NAT64-префиксов или всех режимов браузера.

Прямой перехваченный переход главного окна на другой origin блокируется до запроса; тест popup подтверждает 0 обращений к чужому origin. HTTP redirect по-прежнему может уйти на первый hop без MITM; это известный предел прокси, не дефект изоляции ОС.

## BUG-021 — история и JSON моста

Пустой ответ runner выглядел как «История пуста», а `response.json()` на обрыв давал SyntaxError. История различает loading/ready/error; GET ~15 с, POST `/api/run` не короче лимита прогона; пустое тело не парсится как JSON. После reload открывается последний completed-отчёт; сравнение доступно и в истории.

## BUG-022 — отмена прогона

Интерфейс ждал `runAudit` до конца. Dev: `POST /api/cancel` и AbortSignal, без SIGINT на API. Tauri: `cancel_audit` + PID + `kill_tree`. Поздний успех после стопа не открывается как отчёт.

## BUG-023 — байты WebSocket и PID lock

Upgrade `ws://` шёл через `pipe()` без потолка туннеля. Теперь `relayTunnel`. CLI всегда берёт lock на `runs`. `.audit.lock` содержит PID; пустой файл и живой PID не воруются; мёртвый PID освобождается.

## C07 — снимок ошибки шага

Ранее запись ошибки получала конечный снимок после axe и других проверок. Теперь создаётся отдельный снимок сразу при ошибке; при отказе записи конечный снимок не выдаётся за доказательство шага. Manifest содержит относительные пути и хэши связанных файлов; последовательность событий шагов проверяется перед записью. Структурная сводка DOM частичная, trace остаётся открытой задачей.

## BUG-020 — запуск dev на Windows

`npm run dev` завершался `spawn EINVAL` при запуске `npm.cmd` без оболочки. Vite запускается напрямую через Node; локальные UI и API после исправления поднялись. Проверка проведена на текущей Windows-машине.


## BUG-024 — сторож лишних страниц закрывал вспомогательную страницу axe

`@axe-core/playwright` вставляет свой код через вспомогательную страницу `about:blank`. Сторож посторонних страниц в `runner/audit.mjs` закрывал любой `page`, кроме главной, поэтому каждый axe-прогон падал с `Target page, context or browser has been closed`, а предупреждение подменяло accessibility-находки: `color-contrast` пропадал из отчёта.

Исправление: пока идёт `analyze()`, `about:blank`-страницы не закрываются (все их запросы по-прежнему блокируются), после проверки они закрываются принудительно. Регрессия закреплена `runner/tests/axe-guard.integration.test.mjs`. После исправления smoke даёт 5/9 с `color-contrast`, `/fixed` — 9/9 без accessibility-дефектов.

## BUG-025 — установленная сборка не запускала встроенный Node

В release-сборке на Windows `resource_dir()` возвращает путь в verbatim-форме `\\?\D:\...`. `Command::new(node)` такой аргумент передаёт как есть, а загрузчик модулей Node не разбирает этот префикс: дочерний процесс падал на старте с `EISDIR: illegal operation on a directory, lstat 'D:'`, и в окне появлялось «Проверка завершилась с ошибкой» вместо отчёта. Ни `npm run dev`, ни тесты, где Node вызывается напрямую, этого не видели.

Исправление: `plain_path` в `src-tauri/src/spawn.rs` снимает префиксы `\\?\`, `\\?\UNC\` и `\\.\` перед передачей пути в `node.exe`, `cli.mjs` и `UXPROOF_RUNS_DIR`. Регрессия — `spawn::tests::verbatim_windows_prefixes_are_stripped_before_node`. Проверено прогоном в собранном окне: 9/9 сценариев.

## BUG-026 — двойная блокировка прогона в окне

`run_audit` в Rust держит `.audit.lock` всё время IPC-вызова, а дочерний `runner/cli.mjs` брал тот же lock заново и получал `ConflictError: Уже выполняется другая проверка` — приложение не могло запустить ни одной проверки. В dev API двойной блокировки нет, поэтому дефект проявлялся только в собранном приложении.

Исправление: `runner/audit-lock.mjs` уважает `UXPROOF_LOCK_HELD=1`, который выставляет Rust-сторона при спавне (`spawn.rs`); CLI и dev API по-прежнему берут lock сами. Проверено `scripts/qa-ipc.mjs` в release-окне.

## BUG-027 — интеграционный тест MCP искал файлы не в том каталоге

`mcp-client.integration.test.mjs` собирал пути от `runner/tests` вместо `runner`, поэтому `node` запускал несуществующий `runner/tests/mcp-server.mjs` и тест висел до таймаута. Путь исправлен на `path.resolve(import.meta.dirname, '..')`; прогон также получил собственный временный `UXPROOF_RUNS_DIR`, чтобы не зависеть от остальных тестов.
