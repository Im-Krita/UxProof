Каталоги выбранных зависимостей по-прежнему включаются целиком и требуют контроля содержимого и supply chain.

В Windows x64 release добавлены встроенные Node 24.14.1 и Playwright Chromium Headless Shell revision 1255. Сборщик проверяет Node по официальному SHA-256, включает его лицензию, копирует Chromium из локального кэша по ограниченному списку файлов и записывает метаданные и хэши. Отдельная подпись архива не проверялась. Тест подтверждает отказ при изменённом кэше без удаления предыдущего runtime. После пересборки MSI распакован без установки: все 288 файлов Chromium совпали с манифестом; затем временная распаковка удалена. ## C04 — сравнение: начато

Добавлена функция сравнения одинаковых идентификаторов при наличии одинакового ключа конфигурации. Ключ новых отчётов учитывает URL, сценарии, размеры и опции; старые отчёты без ключа не считаются сопоставимыми. Интерфейс показывает сгруппированные наблюдения, связанные снимки и совпадения ID; несовпадения обозначены как требующие проверки. Неполные прогоны и разные версии схемы не сравниваются. Проверено в локальном Chromium на сохранённых реальных отчётах; API ответов в этом UI-тесте подменялся фикстурами. Для новых отчётов добавлен ключ профиля без pathname; пользователь может явно выбрать прежний отчёт и сопоставить разные пути при одинаковых origin, query, fragment и настройках. Совпадения строятся только по однозначным ruleId и оставшейся части якоря на указанных путях; несовпадения не объявляются исправленными. На реальных прогонах Relay `/` и `/fixed` получено 5/9 и 9/9, для двух ошибок шагов подтверждено повторное выполнение 3/3 и 1/1. UI проверен с реальными отчётами и подменёнными ответами API. Для новых завершающих событий шага сохраняется SHA-256 от origin и пути без query/fragment, а не сам путь. Хэш без соли может быть подобран для предсказуемых адресов; базовый URL и якоря находок по-прежнему могут содержать путь. Статус `resolved` выставляется только для ошибки выполнения шага, когда все ранее ошибочные комбинации прошли с проверенной последовательностью событий на той же или явно сопоставленной странице и нет новой ошибки этого шага. Это не подтверждение общего исправления UX. На Relay `/` → `/fixed` два таких шага получили `resolved`, замечание axe осталось `unverified`; UI проверен с реальными отчётами и подменёнными ответами API. Старые отчёты без идентификатора области страницы, включая ранее созданные события с открытым путём, остаются непроверенными; существующие файлы не переписываются. Находки, которые есть только в after-прогоне, получают статус `new` (исчезнувшие по-прежнему `unverified`, кроме ошибки шага → `resolved`). Fuzzy matching произвольных UX-регрессий нет. C04 не завершена.

Для исчезнувшей ошибки шага интерфейс показывает число ранее ошибочных комбинаций сценария и экрана, в которых тот же шаг прошёл повторно. `resolved` относится только к ошибке выполнения шага, а не ко всему UX; отсутствующие или повреждённые события не засчитываются. Для несовместимых отчётов сравнение суммарных чисел не показывается. Проверено unit-тестом и сборкой интерфейса; отдельный сквозной UI-тест этой индикации пока не проводился.

## C05 — блокировка IPC: частично

В Rust добавлена блокировка аудита на время рабочего процесса и файловая блокировка между экземплярами Tauri с общей папкой app-data. Guard передаётся рабочему потоку и освобождается при завершении или ошибке. Тест Rust проверяет отказ второго процесса, повторный запуск после освобождения, параллельные потоки и освобождение при ошибке и panic. Блокировка web dev API остаётся отдельной; полноценная проверка IPC в окне, тесты упаковки и остальные задачи C05 ещё не выполнены.

Chromium использует локальный аутентифицированный HTTP-прокси: он проверяет адреса и подключается только к полученным разрешённым IP. Кэш DNS между запросами удалён, для DNS установлен таймаут 5 секунд; изменившиеся адреса базового домена отклоняются. Исправлено распознавание IPv4-mapped IPv6, IPv6 link-local и well-known NAT64 `64:ff9b::/96`. Прокси ограничен 128 одновременными входящими соединениями и 10 000 HTTP-запросами/созданиями туннеля за аудит; число отдельных HTTPS-запросов внутри туннеля не подсчитывается. При достижении лимита отчёт помечается неполным.

Локальные тесты покрывают redirect к метаданным, смену DNS, авторизацию и отказ при недоступном прокси, допустимые redirect/cookie/POST/WebSocket, локальный HTTPS через CONNECT и контрольный WebRTC/STUN на Windows. QUIC выключен, используется политика запрета непроксированного WebRTC UDP. HTTPS-тест требует Python с `cryptography` и явно пропускается при его отсутствии. Результаты не доказывают полной сетевой изоляции ОС или защиты от всех нестандартных IPv6-трансляций; ограничения корпоративного HTTP-прокси тоже требуют отдельной проверки.

Прямой переход главной страницы на другой origin, перехваченный Playwright, блокируется до запроса; тест клика и popup подтверждают `targetHits === 0`. Дополнительное окно закрывается, его запросы обрываются. Переход через HTTP redirect по-прежнему может выполниться на первом hop: это предел прокси без MITM. Дальнейшие шаги и снимок чужой страницы останавливаются. Это не полная изоляция ОС; C05 остаётся незавершённой.

## C08 — приватность: частично

Конфигурация нового Tauri-запуска передаётся runner через stdin вместо записи `input.json`. Старые файлы не удаляются автоматически. Снимки маскируют поля ввода, редактируемые области, iframe, canvas и видео; одни и те же маскированные PNG получены при изменении тестовых значений полей, iframe и canvas. Ошибки проверок текста и значения не выводят ожидаемое или фактическое значение; интеграционный тест проверил отсутствие тестовых значений в JSON и HTML. Реальный CLI через stdin выполнил один сценарий Relay (`.uxproof-data/runs/197a26d1-dd8f-44a6-afa6-6fe78dfa96e9`).

Сообщения исключений JavaScript больше не сохраняются; отчёт содержит только ограниченный счётчик. Интеграционный тест на реальном Chromium проверяет отсутствие тестового секрета из исключения в JSON, HTML и manifest.

Значения шагов `fill` и `expectValue` также маскируются при буквальном совпадении в видимом тексте перед сохранением PNG ошибки и итогового PNG. Короткие значения могут скрыть несвязанный текст; преобразования значения, разбиение, изображения и неизвестные секреты не гарантированно маскируются. Тесты на Chromium сравнили снимки с двумя разными тестовыми значениями и проверили, что подменённый вызов модели получает сохранённый маскированный PNG; внешняя модель не вызывалась. Тела ошибок провайдеров больше не записываются, поскольку могут содержать данные или ключи.

Не обещаем поиск всех секретов. Срез: маска `fill`/`expectValue` есть; в отчёте и диалоге доказательства явно сказано, что видимый текст страницы может остаться на PNG. Живой OpenAI не обязателен; локальный стенд достаточен для статуса recommendation. C08 не завершена.

## C06 — геометрия элемента: начато

Текст, селектор и значения полей в эту запись не включаются. При отсутствии элемента или таймауте геометрия не сохраняется. Тесты Chromium проверяют реальные граничные пиксели PNG после прокрутки на мобильном и desktop viewport при DPR 1 и 2; интеграционный тест проверяет запись события. `test:runner` прошёл 75/75, сборка интерфейса и MSI/NSIS через `npm run tauri build` завершились успешно. Геометрия сохраняется только при совпадении замеров до и после снимка; это снижает риск расхождения, но не гарантирует атомарности и не исключает изменения страницы между замерами. В окне доказательства отображается рамка, если PNG однозначно связан с событием и его размеры совпадают с viewport и DPR. UI-тест Chromium проверил положение рамки на реальном отчёте и PNG при подменённых ответах истории и изображения. Остальные сведения об элементе ещё не реализованы. C06 не завершена.

## C07 — доказательства шага: начато

При ошибке сценарного шага отдельный замаскированный PNG снимается до axe и проверки переполнения; запись шага, старая запись проблемы и нормализованное наблюдение ссылаются на него. Конечный PNG прогона остаётся отдельным. Если PNG ошибки не записан, конечный снимок не подставляется как доказательство шага; это проверено тестом с отказом записи. Если другой origin обнаружен после успешной записи PNG, этот PNG удаляется; сбор доказательств чужой страницы прекращается. Состязание с изменением страницы в момент снимка и частичная запись при ошибке полностью не исключены.

Добавлен `artifacts.json` с относительными путями, размерами и SHA-256 для JSON, HTML и связанных PNG; сам manifest в свой список не входит. Пути за пределы каталога и ссылки, разрешающиеся наружу, отклоняются. При ошибке manifest ссылка удаляется из отчёта, который помечается неполным. Тест скопировал файлы в другой каталог и перепроверил хэши; на Relay `441455e2-4424-4643-85ed-9d7af4130df7` проверены 15 хэшей, включая 4 PNG ошибок. Имена новых PNG не содержат ID сценария.

Добавлены события `before`, `action`, `after` и `error` с отдельными ID, временем, контекстом сценария/экрана/шага и ссылкой на PNG ошибки при наличии. Runtime-проверка сверяет их последовательность с результатами шагов; отчёты без событий остаются читаемыми. Схемы событий и manifest проверены на реальном Relay-прогоне `aca4ec9f-0387-49e4-8599-52febf4e0f8d`: 96 событий и 15 артефактов.

К событию ошибки добавлена ограниченная структурная сводка DOM: числовые счётчики и параметры viewport без текста, разметки и значений полей. Обход ограничен 5 000 элементов и временем, покрытие всегда помечено частичным; сводка получается после снимка и не является атомарной с ним. Проверены DPR=2, усечение, iframe, canvas, shadow DOM и отсутствие тестовых строк в сводке.

Добавлен опциональный `trace: on-failure`: при явном включении сохраняется ZIP только для неудачного сценария, а при обнаруженном чужом origin файл отбрасывается. В интерфейсе и отчёте есть предупреждение: trace может содержать DOM, значения и сетевые данные. Для файла действуют ограничения 20 МиБ и 100 МиБ на прогон после записи, путь и хэш включаются в manifest, HTML содержит относительную ссылку. Ограничения не предотвращают временный расход места во время записи. Интеграционный тест проверил успешный, ошибочный и выключенный режимы и отсутствие trace при чужом origin. Сквозной прогон через локальные UI и dev API на Relay `039caa97-24aa-4f82-84d7-691c3f36974e` дал 5 успешных, 4 ошибочных комбинации и 4 файла trace; Tauri IPC этим не проверялся. Прошли 86 тестов runner и сборка MSI/NSIS. Остаётся полная проверка жизненного цикла и обработка всех ошибок/гонок. Проверка путей не заявляется защитой от гонки локального злоумышленника, изменяющего файловую систему во время чтения. C07 не завершена.

## C09/C10 — реестр и правила layout: базовый реестр готов

Добавлен версионированный реестр `runner/rules/registry-v0.1.json`, отдельная JSON Schema и runtime-проверка метаданных. Первое подключённое правило `layout:viewport-overflow` использует измерения ширины документа и viewport и прежний допуск 3 CSS px. Его можно отключить через `options.disabledRules` в проектном JSON; импорт проекта сохраняет настройку, отчёт её записывает, а неправильные ID отклоняются. Тесты реального Chromium проверили переполненную страницу, страницу без переполнения и отключение правила; ресурсы runner проверены вне checkout. Схема проверена Python jsonschema. Прошли 80 тестов runner, Rust-тесты, `test:edge`, исправленный Relay 9/9 и сборка MSI/NSIS. Это только первое правило: общий исполняемый интерфейс детекторов, остальные layout-проверки и полнота реестра остаются открытыми.

## C11 — проверка текста: базовые правила готовы

Реестр содержит два текстовых правила: `copy:duplicate-heading` и `copy:repeated-button-name`. Оба исполняются через общий интерфейс `runner/detectors.mjs` и проверяются в `copy-headings.integration.test.mjs` и `detectors.integration.test.mjs` на реальном Chromium, включая выключение через `disabledRules`.

Реестр содержит `copy:duplicate-heading`: детектор сопоставляет видимые в viewport заголовки и выдаёт гипотезу с PNG, если есть точные повторы после нормализации регистра и пробелов. Исходный текст не переносится из браузера в JSON/HTML; записываются только счётчики. Проверка ограничена 5000 элементами и временем, скрытые и внеэкранные заголовки исключаются, усечение отмечается. Повтор может быть оправданным, автоматически текст не меняется. Гипотезы правил подсчитываются отдельно от рекомендаций модели; правило отключается в настройках. Реальный Chromium проверил позитивный, негативный, скрытый и отключённый случаи, а также отсутствие синтетического текста в JSON/HTML. Видимый текст по-прежнему может попасть в PNG: общая защита секретов C08 не завершена. Тесты runner 83/83, Relay fixed 9/9 и сборка MSI/NSIS прошли. UI проверен в Chromium с реальным отчётом и подменёнными ответами API: счётчик гипотез правила и пояснение отделены от ИИ. Проверки других типов копирайта, связанные элементы и более широкое покрытие остаются открытыми.
